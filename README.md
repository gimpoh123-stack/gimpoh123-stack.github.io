# project_1: 김포 지역 랜덤 밥 메뉴 추천 서비스

## 1. 프로젝트 개요

이 프로젝트는 사용자가 "오늘 뭐 먹지?"라는 고민을 빠르게 해결할 수 있도록 돕는 가벼운 웹 기반 음식점 및 메뉴 추천 서비스이다. 기존 음식점 정보 서비스는 식당명, 위치, 리뷰 중심으로 구성되어 있어 실제로 사용자가 메뉴를 고르기 위해 필요한 정보가 부족한 경우가 많다. 특히 메뉴 구성, 가격, 대표 사진, 정확한 위치 링크, 추가 정보로 이동할 수 있는 경로가 충분하지 않으면 사용자는 여러 사이트를 따로 검색해야 한다.

본 프로젝트는 이러한 불편함을 줄이기 위해 김포 지역을 대상으로 음식점과 메뉴 정보를 한눈에 확인하고, 사용자의 간단한 조건에 따라 적절한 메뉴 또는 음식점을 추천하는 체험형 서비스를 만드는 것을 목표로 한다.

## 2. 기획 배경

기존 음식점 추천 사이트나 리뷰 플랫폼에서는 다음과 같은 한계가 있다.

- 음식점의 메뉴와 가격 정보가 부족하거나 최신 상태인지 확인하기 어렵다.
- 음식점의 정확한 위치, 지도 링크, 공식 페이지 등으로 바로 이동하기 어려운 경우가 있다.
- 제공되는 사진이 리뷰 사진 위주인 경우가 많아 음식점이나 대표 메뉴를 정확히 보여주지 못할 수 있다.
- 사용자가 원하는 조건이 많아질수록 직접 검색하고 비교해야 하는 시간이 늘어난다.
- 추천 결과가 사용자의 상황, 취향, 거리, 가격대 등을 충분히 반영하지 못하는 경우가 있다.

따라서 사용자가 복잡하게 검색하지 않아도 간단한 조건 입력만으로 주변 음식점과 메뉴를 추천받고, 필요한 정보를 바로 확인할 수 있는 서비스가 필요하다고 판단했다.

## 3. 서비스 목표

이 서비스의 핵심 목표는 완성도 높은 대규모 상용 서비스를 만드는 것이 아니라, 실제 사용 가능한 가벼운 체험형 추천 프로그램을 제작하는 것이다. 초기 범위는 김포 지역으로 한정하여 구현 부담을 줄이고, 작은 데이터셋으로도 추천 흐름과 사용자 경험을 검증할 수 있도록 한다.

주요 목표는 다음과 같다.

- 김포 지역 음식점과 메뉴 정보를 정리하여 제공한다.
- 사용자가 조건을 입력하면 조건에 맞는 음식점 또는 메뉴를 추천한다.
- 조건이 거의 없을 때는 랜덤 추천을 통해 빠르게 선택을 도와준다.
- 조건이 많을 때는 최대한 조건에 부합하는 결과를 우선적으로 보여준다.
- 메뉴, 가격, 음식 종류, 위치, 링크, 사진 등 사용자가 판단하는 데 필요한 정보를 함께 제공한다.
- GitHub Pages를 활용하여 별도 서버 없이 정적 웹사이트 형태로 배포할 수 있게 한다.

## 4. 주요 사용자

이 서비스의 주요 사용자는 김포 지역에서 식사 메뉴를 빠르게 정하고 싶은 사람이다.

예상 사용자는 다음과 같다.

- 점심 또는 저녁 메뉴를 고르기 어려운 학생, 직장인, 주민
- 김포 지역 음식점을 잘 모르는 방문자
- 가격대, 음식 종류, 거리 등을 기준으로 빠르게 후보를 보고 싶은 사용자
- 검색 사이트를 여러 번 오가는 과정을 줄이고 싶은 사용자

## 5. 핵심 기능

### 5.1 랜덤 메뉴 추천

사용자가 특별한 조건을 입력하지 않아도 버튼을 누르면 김포 지역의 음식점 또는 메뉴를 무작위로 추천한다. 선택지가 너무 많아 결정을 못 하는 상황에서 빠르게 후보를 제시하는 기능이다.

### 5.2 조건 기반 추천

사용자가 원하는 조건을 입력하면 해당 조건에 가까운 음식점과 메뉴를 추천한다.

예시 조건은 다음과 같다.

- 음식 종류: 한식, 중식, 일식, 양식, 분식, 카페 등
- 가격대: 저렴한 메뉴, 보통 가격대, 특별한 식사
- 위치: 구래동, 장기동, 사우동, 풍무동 등
- 식사 상황: 혼밥, 친구와 식사, 가족 외식, 데이트
- 메뉴 성향: 매운 음식, 국물 음식, 든든한 음식, 가벼운 음식

### 5.3 음식점 상세 정보 제공

추천 결과에는 사용자가 바로 판단할 수 있는 정보를 함께 제공한다.

- 음식점 이름
- 대표 메뉴
- 메뉴 가격
- 음식 종류
- 위치 또는 지역
- 지도 링크
- 공식 사이트 또는 관련 링크
- 대표 이미지
- 간단한 설명

### 5.4 링크를 통한 정보 접근성 개선

기존 서비스에서 부족하다고 느낀 부분 중 하나는 사용자가 추가 정보를 바로 확인하기 어렵다는 점이다. 따라서 추천 결과에는 가능한 한 지도, 공식 페이지, 검색 링크 등을 함께 제공하여 사용자가 추가 검색을 덜 하도록 만든다.

### 5.5 사진 정보 개선

리뷰 사진만 사용하는 경우 음식점의 대표성을 충분히 보여주지 못할 수 있다. 가능하다면 음식점에서 공식적으로 제공한 이미지나 대표 메뉴를 잘 보여주는 이미지를 우선적으로 사용한다. 단, 저작권 문제가 있을 수 있으므로 실제 구현 단계에서는 직접 사용 가능한 이미지, 공개 이미지, 또는 링크 방식 활용을 검토한다.

## 6. 서비스 범위

초기 버전은 김포 지역으로 한정한다. 범위를 좁히는 이유는 다음과 같다.

- 데이터 수집과 정리 부담을 줄일 수 있다.
- 지역 기반 추천 기능을 더 구체적으로 설계할 수 있다.
- 작은 규모에서 먼저 사용자 흐름을 검증할 수 있다.
- 추후 다른 지역으로 확장하기 쉬운 구조를 만들 수 있다.

초기에는 모든 음식점을 포함하기보다 대표적인 몇 개 지역과 음식점을 선정하여 시작한다.

## 7. 데이터 구성 예시

정적 웹사이트로 구현할 경우 음식점 정보는 별도 서버 없이 `JSON` 파일로 관리할 수 있다.

예시 데이터 항목은 다음과 같다.

```json
{
  "name": "예시 식당",
  "area": "김포 구래동",
  "category": "한식",
  "menus": [
    {
      "name": "김치찌개",
      "price": 9000
    }
  ],
  "tags": ["혼밥", "국물", "든든한"],
  "mapUrl": "https://example.com",
  "imageUrl": "images/example.jpg",
  "description": "따뜻한 국물 메뉴를 먹고 싶을 때 추천할 수 있는 식당"
}
```

## 8. 기술 구성

별도 서버를 두지 않고 GitHub를 활용할 계획이므로 정적 웹사이트 형태가 적합하다.

예상 기술 구성은 다음과 같다.

- `HTML`: 페이지 구조 작성
- `CSS`: 화면 디자인 및 반응형 레이아웃 구현
- `JavaScript`: 랜덤 추천, 조건 필터링, 결과 표시 기능 구현
- `JSON`: 음식점 및 메뉴 데이터 관리
- `GitHub Pages`: 웹사이트 배포

이 방식은 서버 비용이 들지 않고, GitHub 저장소만으로 결과물을 공개할 수 있다는 장점이 있다.

## 9. 사용자 흐름

1. 사용자가 웹사이트에 접속한다.
2. 원하는 조건을 선택하거나 아무 조건 없이 랜덤 추천 버튼을 누른다.
3. 서비스가 조건에 맞는 음식점 또는 메뉴를 추천한다.
4. 사용자는 추천 결과에서 메뉴, 가격, 위치, 사진, 링크를 확인한다.
5. 마음에 들지 않으면 다시 추천을 받아 다른 후보를 확인한다.

## 10. 개발 단계

### 1단계: 기본 페이지 제작

- 메인 화면 구성
- 랜덤 추천 버튼 제작
- 추천 결과 카드 UI 제작

### 2단계: 데이터 정리

- 김포 지역 음식점 목록 작성
- 메뉴, 가격, 지역, 카테고리, 태그 정보 정리
- 지도 링크와 이미지 정보 추가

### 3단계: 추천 기능 구현

- 무작위 추천 기능 구현
- 음식 종류, 가격대, 지역 기반 필터링 구현
- 조건이 여러 개일 때 우선순위에 따라 추천하는 방식 구현

### 4단계: 사용성 개선

- 모바일 화면 최적화
- 결과가 없을 때 대체 추천 제공
- 다시 추천하기 기능 추가
- 추천 결과를 보기 좋게 정리

### 5단계: GitHub Pages 배포

- `index.html`, `style.css`, `script.js`, `data.json` 구성
- GitHub Pages 설정
- 실제 접속 링크 확인

## 11. 기대 효과

이 프로젝트를 통해 사용자는 김포 지역에서 식사 메뉴를 더 빠르고 편하게 선택할 수 있다. 또한 단순한 음식점 목록이 아니라 메뉴, 가격, 위치, 링크, 사진 등 실제 선택에 필요한 정보를 함께 제공함으로써 검색 시간을 줄일 수 있다.

개발 측면에서는 서버 없이도 GitHub Pages만으로 동작하는 정적 웹 서비스를 만들어볼 수 있으며, 데이터 기반 필터링과 추천 로직을 직접 구현해보는 경험을 얻을 수 있다.

## 12. 향후 확장 가능성

초기 버전이 완성된 뒤에는 다음과 같은 방향으로 확장할 수 있다.

- 김포 외 다른 지역 추가
- 사용자 취향 저장 기능 추가
- 즐겨찾기 기능 추가
- 메뉴별 평점 또는 메모 기능 추가
- 현재 위치 기반 추천 기능 추가
- 날씨, 시간대, 식사 목적에 따른 추천 기능 추가
- 음식점 데이터 업데이트를 더 쉽게 관리하는 구조 도입

## 13. 프로젝트 한 줄 설명

김포 지역의 음식점과 메뉴 정보를 바탕으로 사용자의 조건에 맞는 식사 메뉴를 가볍게 추천해주는 GitHub Pages 기반 웹 서비스이다.
